# PRD：名单外正式球员代打录入与试训转正提醒

创建日期：2026-10-24；更新日期：2026-10-25  
状态：用户已确认业务口径并要求直接实施（2026-10-25）；本地实现与验证完成，尚未推送、运行远程 CI 或部署。  
适用范围：队内赛录入、解析确认、正式事件保存及相关统计展示。  
本次交付：代码、数据库迁移、回归测试及实施说明。

## 1. 概述

录入员需要记录临时来踢球的正式球员，即使这些人没有出现在当天红、蓝、白三队的分队名单里。只要能够匹配球队全局正式名单，就应允许录入他们的进球和助攻，按代打事件确认实际代表队。

对于被识别为试训、又不在全局正式名单中的人员，系统应弹窗提醒录入员，可在当前页面一键加入正式球员名单，也可保留试训身份。

### 1.1 修改前行为核实

- 解析接口已经向解析器提供全局正式球员及别名；确认页的进球、助攻选择器也使用全局球员列表。
- `lib/match-events.ts` 的 `inspectInternalEvents` 会拒绝没有当天分队的正式进球人或助攻人，提示“球员尚未分队，请先补充当天红、蓝、白分队名单”。确认页面与服务端入库共用这一检查，因此“可以选择”不代表“可以入库”。
- `TrialPlayersPanel` 目前支持确认试训、匹配已有正式球员；没有就地新增正式球员的入口。匹配正式球员还要求选择当天原队，未分队者会被加入分队名单。
- 正式球员的进球、助攻按事件计算；出勤按当天分队名单计算；基础赛季积分按当天原队排名分配。
- 当前特殊事件弹窗把“没有原队”当成试训展示，公开代打标记则依赖原队与代表队不同。两者都需要适配“正式但未分队”的情况。

### 1.2 名词与范围

| 名词 | 本文含义 |
| --- | --- |
| 全局正式名单／最大的名单 | “球员管理”中的全部正式 `Player` 记录，不限于某个比赛日的阵容；沿用当前全部球员可用于录入的行为，不因停用状态重复创建档案 |
| 当天分队名单 | 本比赛日红、蓝、白队的正式阵容记录 |
| 名单外正式代打 | 在全局正式名单中，但没有本比赛日分队记录的正式球员 |
| 原队 | 球员在当天分队名单中的队伍；名单外正式代打没有原队 |
| 本次代表队 | 球员在某个事件中实际代表的队伍，可随事件变化 |
| 转正 | 经录入员明确操作创建全局正式球员，并按下述口径处理当前比赛的身份关联 |

### 1.3 已确认的需求与业务口径

用户明确要求：

1. 全局正式名单中的球员，未进入当天名单也能录入进球、助攻，按代打处理。
2. 被识别为试训且不在全局名单的人员，要有弹窗提醒及一键加入正式名单入口。

以下两项规则已于 2026-10-25 由用户明确选择 A 方案：

- **规则 A1（已确认）——出勤与基础积分：**名单外正式代打只累计实际进球、助攻；不自动增加出勤，不获得队伍排名基础积分。沿用“按当天分队名单计算”的现行规则。已有的人工额外加分与奖项规则保持原样，不能把“无基础积分”理解为取消全部积分资格。
- **规则 A2（已确认）——转正生效范围：**加入全局正式名单后，立即把当前比赛草稿中该试训身份的全部事件关联到正式球员；本场确认入库后才进入正式统计。其他比赛日的历史试训记录保持原样。

配套处理建议：

- **产品建议：**不因转正自动加入当天分队；录入员仍可通过现有分队编辑主动补入原队。身份确认与分队决定分开处理。
- **产品建议：**同一批识别出的多人合并在一个弹窗中逐人处理，每人提供一键转正入口；不增加独立的批量转正管理系统。

实施本需求时，替代旧需求中“正式事件参与者必须先分队”和“纠正正式身份必须补选原队”的限制。其余试训、乌龙、二次确认和草稿保护规则继续适用。

## 2. 目标

- 已存在的正式球员无需补进当天分队，即可完成进球人、助攻人两种角色的录入与确认入库。
- 录入员无需离开比赛录入页面，即可将一个无冲突的试训姓名加入全局正式名单。
- 每个名单外正式代打事件在入库前明确得分队，并经过人工二次确认。
- 转正覆盖本场该身份的所有事件，避免同一人部分计正式、部分仍计试训。
- 重复提交、重新解析和重新确认不重复创建球员，不重复累计数据。

## 3. 用户故事与验收标准

### US-001：允许全局正式球员作为名单外事件参与者

**描述：**作为录入员，我希望全局名单中未参加当天分队的正式球员也能作为进球人或助攻人，以便完整记录真实比赛。

**验收标准：**

- [x] 全局存在球员甲、当天没有甲的分队记录时，甲作为普通进球人能够通过身份校验。
- [x] 甲只作为助攻人时也能够通过身份校验；进球人和助攻人均未分队的事件同样支持。
- [x] 名单外正式参与者按角色识别为代打，不因已经填写得分队而跳过特殊事件二次确认。
- [x] 得分队缺失时要求录入员补选；选择本节参赛双方之外的队伍时拒绝入库。
- [x] 后端校验正式球员 ID 确实存在于全局名单；伪造或已删除的 ID 返回明确错误，不仅依赖前端选择器。
- [x] 允许本场有效试训身份继续参与混合事件；不能放宽对待确认、跨比赛日或双重身份的限制。
- [x] 保存名单外代打事件不新增 `TeamAssignment`，不替换其他人的分队。
- [x] 相关 Vitest 与类型检查通过。

### US-002：识别、编辑并确认名单外代打

**描述：**作为录入员，我希望解析和手工编辑都能明确展示正式代打身份，以便核对得分与个人统计归属。

**验收标准：**

- [x] DeepSeek 解析和本地规则解析均可按全局正式姓名或已登记别名识别名单外球员；不能仅因未分队就改为试训。
- [x] 模糊姓名仍进入待确认；支持录入员选择已有正式球员，且无需补选原队。
- [x] 事件选择器保留全局正式球员；名单外参与者展示“正式球员 · 当天未分队 · 代打”。
- [x] 同一正式球员可在不同事件中代表不同队伍，每条事件单独确定得分队。
- [x] 二次确认弹窗区分“已分队正式代打”“未分队正式代打”“试训”，并按真实身份说明个人进球、助攻是否计入。
- [x] 按 A1，未分队正式代打的弹窗提示为“进球／助攻计本人；未加入当天分队，不增加出勤和排名积分”。
- [x] 修改参与者、身份、得分队、数量或事件类型后，旧特殊事件确认失效。
- [x] 取消二次确认保留编辑内容，已确认比赛的正式事件和统计保持原样。
- [x] 类型检查通过；在浏览器验证进球、助攻、混合事件、补选得分队及取消确认。

### US-003：弹窗提示未知试训人员加入正式名单

**描述：**作为录入员，我希望发现全局名单外人员时立即得到提醒，并在当前页面决定其身份。

**验收标准：**

- [x] 队内赛分队识别，包括文本和图片入口，以及赛后文本解析产生新的未知试训人员时，展示身份处理弹窗。
- [x] 打开已有解析结果且仍存在未处理的未知试训人员时，也展示提醒，避免只有新解析入口能触发。
- [x] 同一批未知身份合并展示；同一人在多个事件中出现只显示一条身份记录。
- [x] 每条记录显示原始姓名、可编辑的正式姓名；有事件时展示相关节次供核对。
- [x] 每条记录提供“加入正式名单”“匹配已有球员”“保留试训”操作。
- [x] 无名称冲突时，姓名默认填好，点击一次“加入正式名单”即可创建并关联；球衣号、位置、头像不是必填项。
- [x] 打开弹窗、关闭弹窗或点击“稍后处理”都不会自动创建正式球员；稍后处理的身份仍为待确认。
- [x] 点击“保留试训”相当于明确确认该试训身份，本次继续编辑不反复弹出；试训区域保留后续转正入口。
- [x] 新增未知身份会再次提示；只重新渲染、修改比分不会反复提示同一个已处理身份。
- [x] 全局已有正式姓名或别名命中时，引导关联已有记录，不展示为可直接新建的同名人员；模糊候选不自动合并。
- [x] 类型检查通过；在浏览器验证单人、多人、稍后处理、保留试训和匹配已有球员。

### US-004：创建正式球员并一致地转换当前比赛身份

**描述：**作为录入员，我希望一键转正后本场数据完整关联到同一名正式球员，失败或重试不会造成重复档案和遗漏事件。

**验收标准：**

- [x] 成功后全局名单立即出现该正式球员，当前页面的正式球员选项同步更新，身份行显示成功结果。
- [x] 按 A2，当前比赛中同一试训 ID 对应的所有进球人、助攻人、乌龙球员引用统一转换；保留原始文本、节次、数量、事件性质和得分队。
- [x] 本场名称纠正映射继续有效，重新解析不会把刚转正的人重新识别成另一个试训身份；不自动写入全局别名。
- [x] 已有当天分队的正式球员保留原队；无分队的正式球员采用名单外代打规则，不要求凭空指定原队。
- [x] 对已有比赛日，转正结果及本场身份草稿可在重新加载后恢复；创建正式球员与保存对应身份映射不能产生不可恢复的部分成功。
- [x] 对尚未保存的录入表单，成功创建的全局球员立即生效，身份映射随本次比赛保存；放弃表单不会删除已创建的全局球员。
- [x] 已确认比赛中的转正先影响草稿；正式事件、旧试训记录及榜单在重新确认事务成功前保持原样。
- [x] 名称为空、与其他球员姓名／别名冲突、无权限或保存失败时，给出可读错误，保留待处理内容。
- [x] 重复点击、响应超时后重试、并发创建同名人员不会生成重复正式球员；并发身份冲突要求录入员核对现有记录。
- [x] 创建成功但随后取消比赛确认时，全局正式档案仍保留；界面提前说明“加入名单立即生效，本场数据确认入库后计入统计”。
- [x] 相关 Vitest 与类型检查通过；在浏览器验证刷新恢复、失败重试及已确认比赛的草稿保护。

### US-005：统计、展示和重新编辑保持一致

**描述：**作为球队成员，我希望名单外代打与转正后的个人数据可在榜单、球员详情和战报中核对。

**验收标准：**

- [x] 按 A1，无分队球员甲在本场进球 2 次、助攻 1 次且无额外加分时，本场对其累计贡献为进球 +2、助攻 +1、出勤 +0、基础积分 +0。
- [x] 普通进球计入本人及该事件得分队；助攻计入实际正式助攻人，团队比分不因保存明细再次累加。
- [x] 按 A2，试训人员转正后本场已确认的全部普通进球、助攻计入该正式球员；其他比赛日历史试训数据不自动转换。
- [x] 继续保留试训时，试训自身不进入正式个人榜单，配合的正式球员正常获得进球或助攻。
- [x] 名单外正式球员的乌龙可沿用特殊事件流程保存；只增加独立乌龙数，不增加普通进球，不产生助攻。
- [x] 已分队球员仍按原队获得一次出勤和排名积分，包括原规则下的临时未到场者。
- [x] 按 A1，场均沿用当前公式；出勤分母为 0 时显示 0，不出现 `NaN` 或无穷值，不为计算场均虚增出勤。
- [x] 名单外球员的比赛记录可见；分享页、导出战报和个人记录按实际角色显示代打标记，不能被错误显示为试训。
- [x] 历史缺少原队快照的事件保持兼容，不能仅凭空快照把所有旧事件标记为名单外代打。
- [x] 重新打开并确认同一比赛不重复累计事件或积分；人工将球员补入当天原队后，重新确认按新正式阵容计算。
- [x] 统计测试、相关 API 测试和类型检查通过；在浏览器验证榜单、球员详情、战报及再次编辑。

## 4. 功能需求

- FR-1：系统必须允许全局正式名单中的球员在未分队时参与队内赛普通进球事件。
- FR-2：系统必须允许全局正式名单中的球员在未分队时参与队内赛助攻事件。
- FR-3：系统必须在服务端验证事件引用的正式球员存在。
- FR-4：系统必须把名单外正式参与者按各自角色纳入代打二次确认。
- FR-5：系统必须将每条队内赛事件的得分队限定为对应小节的参赛双方之一。
- FR-6：系统必须在缺少明确得分队时要求人工补选。
- FR-7：系统必须允许同一名单外正式球员在不同事件中代表不同队伍。
- FR-8：系统必须保持身份关联操作与当天分队操作相互独立。
- FR-9：系统必须按 A1 使用当天分队名单计算出勤。
- FR-10：系统必须按 A1 只向有当天原队的球员分配该队排名基础积分。
- FR-11：系统必须在识别出全局名单外的未知试训身份时弹窗提醒。
- FR-12：系统必须为每个可新建身份提供一键加入正式名单入口。
- FR-13：系统必须允许录入员明确保留试训身份。
- FR-14：系统必须允许录入员把待处理身份匹配到已有正式球员。
- FR-15：系统必须拒绝未满足现有姓名及别名唯一性约束的正式档案创建请求。
- FR-16：系统必须按 A2 将本场同一试训身份的全部事件引用转换到对应正式球员。
- FR-17：系统必须保留转正事件的原始文本和比赛内容。
- FR-18：系统必须在重新解析当前比赛时保留已保存的人工身份映射。
- FR-19：系统必须在相关身份或事件内容变化后使旧二次确认凭证失效。
- FR-20：系统必须将已确认比赛的身份修改保留为草稿，直到重新确认事务成功。
- FR-21：系统必须在重试转正请求时避免重复创建同一正式球员。
- FR-22：系统必须按 A2 保留其他比赛日的历史试训身份。
- FR-23：系统必须在比赛展示中区分名单外正式代打与试训身份。
- FR-24：系统必须在重新确认比赛时替换旧正式事件，避免重复累计。
- FR-25：系统必须继续阻止乌龙事件包含助攻引用。
- FR-26：系统必须继续根据确认后的数据库事件重新计算榜单。

## 5. 非目标

- 不改变三队赛程、比分、排名规则和已分队球员的基础积分分配方式。
- 不恢复已撤销的个人积分资格开关。
- 不按进球、助攻或代打次数自动补分队，也不推断完整出场时长。
- 不自动把全部试训人员转成正式球员，不自动追加全局别名。
- 不跨比赛日按同名合并试训记录，不批量追溯历史试训统计。

## 6. 交互建议

身份弹窗标题建议为“发现未加入正式名单的球员”。说明：“请核对姓名。加入正式名单后，本场数据将在确认入库后计入个人统计；也可以继续按试训录入。”
