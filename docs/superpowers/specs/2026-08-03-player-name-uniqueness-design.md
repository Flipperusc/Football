# 球员名称唯一性设计

## 目标

球员标准姓名与球员别名共享同一个名称空间。系统不得新增或修改出与任何已有标准姓名或别名相同的名称，并应向管理员明确说明冲突来源。

## 名称判定

沿用球员名单导入的 `playerImportKey` 规则生成比较键：清理名单序号和标点、统一全角字符、移除空白，并将英文字母转为小写。因此 `BOBO` 与 `bobo`、`张 三` 与 `张三` 均视为同名。

空名称仍由现有 Zod 校验拒绝，不进入占用检查。

## 共享校验

在服务端抽出一个球员名称占用模块，集中完成以下工作：

- 从标准姓名和别名生成统一比较键。
- 查询已有球员的标准姓名和所有别名。
- 支持排除正在编辑的球员或指定的别名记录。
- 返回冲突类型、冲突文本及所属球员，供 API 生成一致的错误提示。

该模块只负责名称占用判断，不负责 HTTP 响应或数据库写入。

## 接口行为

### 单个新增球员

`POST /api/players` 在写入前检查提交的标准姓名。若与已有标准姓名或别名冲突，返回 HTTP 409。错误消息分别说明“与球员名称……重复”或“已被球员……用作别名”。

### 批量导入球员

`POST /api/players/bulk` 使用同一比较规则检查：

- 当前导入名单内部的重复名称；
- 已有标准姓名；
- 已有别名。

批量导入保持现有交互：冲突行进入 `skipped`，其他合法球员继续创建。跳过原因需说明冲突来源。

### 编辑球员姓名

`PATCH /api/players/[id]` 仅在请求包含 `name` 时检查名称占用，并排除当前球员自身的标准姓名。若该名称被其他球员的标准姓名或任何别名占用，返回 HTTP 409。

当前球员自己的别名也占用名称，因此不能把标准姓名改成自己的某个别名。

### 新增别名

`POST /api/players/[id]/aliases` 在写入前检查别名。别名不得与任何球员的标准姓名或任何已有别名重复，包括当前球员自己的标准姓名和已有别名。冲突时返回 HTTP 409，并明确说明冲突来源。

## 前端行为

球员管理页继续使用现有 `requestJson` 错误处理。单个新增、编辑姓名和新增别名的提交函数捕获服务端错误，通过 Ant Design 消息组件展示 API 返回的冲突说明，并保留表单内容供管理员修改。

批量导入继续显示已创建与已跳过数量；服务端返回的逐行原因保留在响应中，不改变当前批量导入的部分成功语义。

## 并发与数据约束

本次采用应用层共享校验，不新增数据库占用表。它统一所有当前应用写入口，但不承诺阻止绕过应用直接写数据库或两个极小时间窗口内的并发写入。若未来需要数据库级严格互斥，可再引入统一名称占用表并回填历史数据。

## 测试

新增共享模块单元测试，至少覆盖：

- 标准姓名与已有标准姓名冲突；
- 标准姓名与已有别名冲突；
- 英文大小写、全角字符和空白归一化冲突；
- 编辑时排除当前标准姓名，但不排除自己的别名；
- 新增别名与标准姓名或别名冲突；
- 无冲突时返回可用。

同时运行完整 Vitest 测试和 Next.js 生产构建，确认类型、页面及 API 编译正常。
